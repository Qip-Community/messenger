# QIP Community — настоящий браузерный мессенджер

Общий чат для всех участников + личные сообщения между любыми
зарегистрированными пользователями. Регистрация по email+паролю.
Бэкенд — Firebase (Authentication + Firestore), поэтому сайт остаётся
статикой и спокойно живёт на GitHub Pages, а сообщения реально
доставляются между разными людьми и разными браузерами в реальном времени.

## Файлы
- `index.html` — разметка (экран входа/регистрации + сам мессенджер)
- `style.css` — оформление в духе классического QIP
- `firebase-config.js` — сюда вставляешь ключи своего Firebase-проекта
- `app.js` — вся логика: аутентификация, список пользователей, общий чат, личка
- `firestore.rules` — правила безопасности базы (кто что может читать/писать)

## Шаг 1. Создай проект в Firebase (бесплатно)
1. Зайди на https://console.firebase.google.com и нажми **"Добавить проект"**.
2. Дай имя, например `qip-community`, остальные настройки — по умолчанию.
3. В боковом меню открой **Build → Authentication → Get started**,
   на вкладке **Sign-in method** включи провайдер **Email/Password**.
4. В боковом меню открой **Build → Firestore Database → Create database**,
   выбери **Start in production mode** (правила подставим свои), любой регион.
5. В **Project settings → General → Your apps** нажми иконку **`</>`**
   (веб-приложение), дай имя, Firebase покажет объект `firebaseConfig`.

## Шаг 2. Подставь ключи
Скопируй значения из `firebaseConfig` в файл `firebase-config.js`
(там уже подготовлены нужные поля — просто замени `"ВСТАВЬ_СЮДА"`).

## Шаг 3. Загрузи правила безопасности
В Firebase Console: **Firestore Database → Rules** — вставь туда содержимое
файла `firestore.rules` из этого проекта и нажми **Publish**.
Без этого шага либо никто не сможет писать сообщения, либо (что хуже)
у всех будет доступ ко всем личным перепискам.

## Запуск локально
Открой `index.html` через любой локальный сервер (просто открыть файл
двойным кликом тоже обычно работает, но надёжнее через сервер):
```
npx serve .
```

## Публикация на GitHub Pages
1. Создай репозиторий, например `qip-community`.
2. Залей все файлы:
   ```
   git init
   git add .
   git commit -m "QIP Community — real chat on Firebase"
   git branch -M main
   git remote add origin https://github.com/<твой-логин>/qip-community.git
   git push -u origin main
   ```
3. **Settings → Pages → Source** → ветка `main`, папка `/ (root)`.
4. Сайт появится на `https://<твой-логин>.github.io/qip-community/`.
5. Важно: в Firebase Console → **Authentication → Settings → Authorized domains**
   добавь этот адрес (`<твой-логин>.github.io`), иначе вход/регистрация
   с этого домена будут блокироваться.

## Индексация в Google Search Console
1. https://search.google.com/search-console → **Добавить ресурс** → "Префикс URL" →
   вставь адрес твоего GitHub Pages сайта.
2. Подтверди владение через HTML-тег (вставь `<meta name="google-site-verification" ...>`
   в `<head>` файла `index.html` и запушь) или через файл-подтверждение.
3. В разделе **"Проверка URL"** запроси индексирование главной страницы.

## Как это работает и что важно понимать
- Данные хранятся в Firestore — бесплатный лимит щедрый, но не бесконечный
  (см. Firebase Pricing, план Spark). Для чата с друзьями/сообществом хватит с запасом.
- Статус "онлайн/отошёл/не беспокоить" сейчас выставляется вручную через
  выпадающий список — это не настоящее автоопределение присутствия.
  Для честного "человек действительно онлайн" нужна Firebase Realtime Database
  с `onDisconnect()` — можно добавить отдельным шагом, если понадобится.
- `firebase-config.js` не секретный файл — эти значения и так видны в исходном
  коде любого Firebase-сайта. Реальную защиту данных обеспечивают
  `firestore.rules`, а не сокрытие конфига.
